# Engineering Transformation Roadmap: Infra-Tycoon

## Executive Summary
This roadmap outlines a multi-phase transformation plan to evolve **Infra-Tycoon** from a frontend-heavy proof-of-concept into a highly scalable, production-grade 3D data center simulation platform capable of modeling thousands of racks and real-time telemetry streams.

---

## Current Architecture Strengths
- **Visual Fidelity**: High-quality R3F implementation with expressive animations.
- **Feature Depth**: Comprehensive set of features (Networking, Power, Thermal, Economics, Terminal).
- **Modern Stack**: React 19, Vite, Tailwind, Zustand provide a fast development loop.

---

## Vision Gap Analysis
| Current State | Target State (Production Grade) |
| :--- | :--- |
| Monolithic Global State | Domain-Driven Fragmented Stores |
| React-managed 3D Entities | ECS (Entity-Component-System) for Sim entities |
| Main-thread Simulation | Web Worker-based Physics Engine |
| Individual Mesh Rendering | Instanced Rendering & LOD |
| LocalStorage Persistence | Scalable Backend (Go/Rust + TimescaleDB) |

---

## Priority Matrix
- **High Impact / High Urgency**: Store Fragmentation, Instanced Rendering.
- **High Impact / Medium Urgency**: Web Worker Sim, ECS Migration.
- **Medium Impact / Low Urgency**: AI Automation, Advanced CFD modeling.

## Multi-Phase Implementation Plan

### Phase 1: Critical Stabilization & Fragmentation (Immediate)
**Objectives**: Reduce monolithic file sizes and prevent "God Object" anti-patterns.
- **Tasks**:
  - [ ] Split `useInfraStore.ts` into `useWorldStore.ts`, `useSimStore.ts`, and `useUIStore.ts`.
  - [ ] Decompose `Scene.tsx` into atomic components: `RackContainer`, `ServerUnit`, `PortArray`.
  - [ ] Implement `React.memo` and focused Zustand selectors to minimize re-renders.
- **Files to Modify**: `src/store/useInfraStore.ts`, `src/components/world/Scene.tsx`, `src/App.tsx`.

### Phase 2: Rendering Performance Overhaul
**Objectives**: Support 100+ racks at 60fps.
- **Tasks**:
  - [ ] Implement `instancedMesh` for `StatusLED` and `HardwarePort`.
  - [ ] Create a `GeometryManager` to share geometries across thousands of instances.
  - [ ] Implement basic LOD (Level of Detail) that hides internal server hardware when zoomed out.
- **New Files**: `src/components/world/InstancedManager.tsx`.

### Phase 3: Simulation Engine Separation
**Objectives**: Ensure UI remains responsive regardless of simulation complexity.
- **Tasks**:
  - [ ] Create `SimulationWorker.ts` using Web Workers.
  - [ ] Port `powerEngine.ts` and `processTick` logic to the worker.
  - [ ] Implement high-frequency telemetry bridging (Worker -> SimStore).
- **New Files**: `src/workers/simulation.worker.ts`, `src/physics/SimulationBridge.ts`.

### Phase 4: ECS Migration (Scalability)
**Objectives**: Scale to 10,000+ entities (cables, servers, telemetry points).
- **Tasks**:
  - [ ] Integrate `bitecs` or `ecsy` for core entity management.
  - [ ] Transition `InfraNode` from a React component to an ECS entity.
  - [ ] Separate "Sim Entities" from "View Components".

### Phase 5: Persistence & Backend Integration
**Objectives**: Support enterprise-scale save games and multi-user collaboration.
- **Tasks**:
  - [ ] Design a REST/WebSocket API for state synchronization.
  - [ ] Implement PostgreSQL + TimescaleDB for telemetry history.
  - [ ] Add Auth (RBAC) for "Operator" vs "Admin" roles.

## 1-Year Architecture Vision
A fully distributed "Digital Twin" platform where:
- The 3D view is just one of many clients (Web, VR, Mobile).
- A cluster of workers handles real-time airflow and power simulations.
- Real-world sensor data (IoT) is piped into the simulation to create a live mirror of physical data centers.
